# 아날로그 시계 추가 및 이미지 렌더링 최적화 가이드

본 문서는 LVGL 기반 임베디드 장치에서 아날로그 시계를 구현하거나 추가할 때, CPU 부하를 최소화하고 터치 및 시스템 성능을 안정적으로 유지하기 위해 반드시 준수해야 하는 가이드라인을 설명합니다.

---

## 1. 렌더링 방식 선택 (벡터 vs 이미지 회전)

* **실시간 벡터 드로잉 (LVGL Lines/Arcs)**
  * **장점**: 메모리 사용량이 극히 적고 임의의 크기 조절이 쉬움.
  * **단점**: 매 프레임 수학적 좌표 계산(sin, cos) 및 안티앨리어싱 선 렌더링 연산을 수행하므로 CPU 부하가 매우 높음.
* **이미지 회전 렌더링 (LVGL Image Rotation)**
  * **장점**: 복잡한 디자인(그림자, 질감, 테두리 등)을 완벽히 표현할 수 있고, 이미지 캐시를 활용하면 CPU 수학 연산량이 최소화됨.
  * **단점**: 디코딩된 이미지를 상주시킬 PSRAM 메모리가 필요함.
  * **결론**: **시침, 분침과 같이 형태가 디테일하고 1분 주기로 갱신되는 바늘은 이미지를 회전(Rotation)하여 표시하고, 매 초 빠르게 움직이는 초침만 단순 벡터 라인으로 그리는 구조가 최적입니다.**

---

## 2. LVGL 이미지 회전 (`lv_img_set_angle`) 핵심 구현 규칙

### 2.1 각도(Angle) 계산
* LVGL의 회전 각도는 **0.1도 단위**의 정수값을 사용합니다. (360도 = `3600`)
* 이미지 리소스의 원래 모양이 수직 위쪽(12시 방향)을 향하고 있을 때 회전각 `0`이 12시를 가리키게 되며, 각도 값이 증가할 때 **시계 방향**으로 회전합니다.
* **시침 각도 계산**: 
  $$\text{h\_angle} = ((\text{hour} \pmod{12}) \times 300 + \text{minute} \times 5) \pmod{3600}$$
* **분침 각도 계산**: 
  $$\text{m\_angle} = (\text{minute} \times 60) \pmod{3600}$$

### 2.2 피벗(Pivot) 및 정렬(Align) 오프셋 공식
이미지 회전축(Pivot) 위치가 화면 중앙에 정확히 오게 하려면, 단순히 `lv_img_set_pivot`만 호출해서는 안 되며 **이미지 정렬 위치에 오프셋 보정**을 적용해야 합니다.
LVGL은 `lv_obj_align(obj, LV_ALIGN_CENTER, 0, 0)` 정렬 시 이미지의 **기하학적 중심**을 화면 중앙에 배치하기 때문입니다.

* **보정 공식 (화면 중앙 정렬 기준)**:
  * 이미지 크기: $W \times H$
  * 설정할 회전 피벗 좌표: $(p_x, p_y)$
  * **정렬 오프셋 계산**:
    $$\text{align\_offset\_x} = \frac{W}{2} - p_x$$
    $$\text{align\_offset\_y} = \frac{H}{2} - p_y$$
  * 그림자 오프셋 적용 시 계산된 정렬 오프셋에 그림자 오프셋(예: $+4\text{px}$)을 더해 줍니다.

* **실제 적용 예시 (Tesla 스타일 시계)**:
  * **시침 (`hour.png`, 27x210, 피벗: 13, 180)**:
    * $\text{align\_offset\_y} = \frac{210}{2} - 180 = 105 - 180 = -75$
    * `lv_obj_align(hour_img, LV_ALIGN_CENTER, 0, -75);`
    * `lv_img_set_pivot(hour_img, 13, 180);`
  * **분침 (`minute.png`, 23x275, 피벗: 11, 245)**:
    * $\text{align\_offset\_y} = \frac{275}{2} - 245 = 137.5 - 245 \approx -107$
    * `lv_obj_align(minute_img, LV_ALIGN_CENTER, 0, -107);`
    * `lv_img_set_pivot(minute_img, 11, 245);`

## 3. 리소스 및 태스크 최적화 (성능 병목 방지)

### 3.1 갱신 주기(Refresh Interval) 제한
* 매초 초침이 갱신되어 화면 전체가 무효화되더라도, 시침과 분침의 회전 각도는 **분이 변경될 때만** (`minute != last_min || hour != last_hour`) 계산 및 호출하도록 예외 조치를 취합니다.
* 불필요하게 `lv_img_set_angle`을 매초 호출하는 낭비를 방지합니다.

### 3.2 LVGL 이미지 캐시 용량 조절 (`lv_img_cache_set_size`)
* **가장 중요**: 화면에 동시에 출력해야 하는 전체 이미지 에셋의 개수(배경, 시침, 분침, 각각의 그림자, 중앙 핀 등)보다 **이미지 캐시 크기가 무조건 크게 설정**되어야 합니다.
* 캐시 크기가 부족할 경우, 화면 갱신(초침의 1초 주기 무효화) 시마다 캐시 공간 부족으로 인한 **디스크(LittleFS) 재로드 및 PNG 디코딩 연산(Cache Thrashing)이 무한히 발생**합니다.
* 이는 CPU 점유율을 100%로 만들고 I2C 통신 인터럽트를 마비시켜 **터치가 전혀 동작하지 않는 먹통 현상**을 유발합니다.
* 시계 화면 구성을 위해 이미지 캐시 크기를 넉넉히 설정해 두어야 합니다 (예: `lv_img_cache_set_size(16)`).

### 3.3 Z-order (레이어 순서) 관리
* 매초 렌더링 시 특정 객체를 강제로 위로 올리기 위해 `lv_obj_move_foreground()`를 호출하는 것은 레이아웃 무효화를 불필요하게 유발하므로 피해야 합니다.
* 컴포넌트를 생성할 때 Z-order 아래에서부터 위 순서대로 순차 생성하면 이 불필요한 호출을 완전히 제거할 수 있습니다:
  1. 배경 이미지 (`s_clock3_bg_img`)
  2. 시침/분침 그림자 이미지
  3. 시침/분침 본체 이미지
  4. 초침 라인
  5. 초침 데두리 원형 도트
  6. 중앙 핀 이미지
